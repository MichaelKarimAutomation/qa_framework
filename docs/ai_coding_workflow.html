AI Coding Workflow — Human Steps

Cut-and-dry walkthrough of what the human does when working with Claude Code in this repo. Claude does the rest automatically per CLAUDE.md. If you need the why behind any step, read CLAUDE.md — that's the operating contract.

Point A → Point B (single feature)

  1. Branch from master. 
    git checkout master
git pull
git checkout -b task/<short-kebab-name>
    Use the task/ prefix (or feature/ / fix/) so the CI merge gate recognizes the branch.
  2. Tell Claude Code what you want. Just describe the change in plain language. Don't worry about the pipeline plumbing — hooks force Claude to create the task folder, write tests, run pytest, invoke the local reviewer, and commit with the required trailers.
  3. Watch progress in ai_coding/active/<task>/PROGRESS.md. Claude updates it at meaningful boundaries (inner loop green, after local review, after commit). You don't need to interact with it.
  4. If Claude halts urgently, intervene. Halt tags appear in disagreements.log in the task folder:
    • [TEST_CAP_REACHED] — tests still failing after 3 fix attempts.
    • [FULL_SUITE_FAILED] — a previously-untouched test regressed.
    • [CAP_REACHED] — local reviewer kept flagging issues across 2 review iterations.
    Read the log, decide what to do (fix it yourself, redirect Claude, abandon).
  5. Push the branch and open the PR. 
    git push -u origin task/<name>
gh pr create --base master
    The CI merge gate runs automatically. It allows the PR if every commit on the branch carries valid AI-Verdict: and AI-Task: trailers.
  6. Squash-merge when CI is green. Standard GitHub squash-and-merge. Delete the branch from the prompt after merge.

Periodic upkeep

  1. Run a deep review before /clear. Same Claude Code session that just finished a feature is the right place: ask for a deep review. Claude reads every diff, log, and source file, flagging anything that looks off — especially in tasks tagged [CAP_REACHED] or [OVERRIDE].
  2. Archive reviewed clean-PASS task folders. After deep review, move ai_coding/active/<task>/ with STATUS=PASS to ai_coding/archive/<task>/. Leave [CAP_REACHED] and [OVERRIDE] folders in active/ until you handle them manually (or move them to quarantine/).
  3. Then /clear before the next feature. Clear context, then start the next branch from step 1 above. Do not /clear before the deep review — you'd destroy the context the review depends on.

What you never have to do

  • Create the task folder manually — the PreToolUse hook forces it.
  • Remember to add the AI trailers — the commit-msg hook rejects commits without them.
  • Worry about Claude editing files before the folder exists — same hook blocks edits outside ai_coding/active/<task>/ until you (or Claude) create the folder.
  • Manually route diffs to task folders — the post-commit hook does it.

Common edge cases

The CI merge gate failed on my PR

Two causes. (1) A commit on the branch is missing trailers — find the offending SHA in the workflow log, amend or replace that commit. (2) AI-Verdict: CAP_REACHED or OVERRIDE appears on a commit — the gate blocks these so a human reviews them before merge. Decide whether the override is acceptable, then either rewrite history with a passing verdict or merge admin-override.

I want to work on something small and non-pipeline

Use a branch name that doesn't match feature/*, fix/*, or task/*, and don't touch ai_coding/active|archive|quarantine/. The gate will exit silently and your PR goes through normal review. Note: the PreToolUse hook still blocks Claude from editing source files without a task folder — pass --no-verify on local commits if you want to bypass the commit-msg hook for non-pipeline work too.

Claude went off the rails / I want to abandon a task

Delete the task folder under ai_coding/active/, reset the branch (git reset --hard origin/master), and start over. The pipeline keeps no global state outside the folder.
