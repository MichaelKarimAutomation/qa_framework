AI Coding Workflow (Human Steps)

What you do when using Claude Code in this repo. Claude does the rest of the work on its own. If you want the full reasoning behind any step, read CLAUDE.md. That file is the rule book.

Steps

  1. Update master and start a new branch. 
    git checkout master && git pull
git checkout -b task/short-name
    Pick a short name written in lowercase words joined by hyphens (for example task/add-login-button). The name should say what the change is about. On Windows PowerShell, replace && with ;.
  2. Tell Claude Code what you want in plain words. Just describe the change. Claude follows the pipeline on its own: it creates the task folder, writes tests, runs them, asks the local AI reviewer to check the work, and makes a commit with the special tag lines at the bottom. Hooks back this up by blocking edits outside the task folder and rejecting commits missing the tag lines.
  3. Watch progress in ai_coding/active/<your task>/PROGRESS.md. Claude writes to this file at the important moments. You do not edit it yourself. Reading it tells you what is finished and what is left.
  4. Check disagreements.log when Claude flags an issue. Open ai_coding/active/<your task>/disagreements.log. You will see one of these tags:
    • [TEST_CAP_REACHED]: tests still failed after 3 fix attempts. No commit was made.
    • [FULL_SUITE_FAILED]: something Claude did not touch is now broken. No commit was made.
    • [CAP_REACHED]: the local reviewer kept finding problems over 2 attempts. Claude committed anyway and is flagging it for you.
    • [OVERRIDE]: Claude disagreed with the local reviewer and proceeded. Claude committed and is flagging it for you. The merge gate will block the pull request until you clear it.
    Read the log, then decide. For the two halt tags (no commit yet), you can fix the problem yourself, give Claude new instructions, or drop the task. For [CAP_REACHED] or [OVERRIDE], the commit already exists, so you fix on top, redirect Claude, or reset the branch to undo the commit.
  5. Ask Claude for a deep review. This is required. In the same Claude Code chat, paste this prompt: 
    Do a deep review of the changes on this branch. Find this branch's
task folder under ai_coding/active/ (use the AI-Task trailer on a
recent commit on this branch), read its STATUS file and
disagreements.log, flag any [TEST_CAP_REACHED], [FULL_SUITE_FAILED],
[CAP_REACHED], or [OVERRIDE] tags, and tell me the next step.
    Claude will read every change, every log file, and every affected source file for this branch only. Take its findings seriously, especially anything tagged [CAP_REACHED] or [OVERRIDE].
  6. Move this branch's finished task folder into ai_coding/archive/. Ask Claude to do it with this prompt: 
    If this branch's task folder under ai_coding/active/ has STATUS=PASS,
move it into ai_coding/archive/. If it is tagged CAP_REACHED or
OVERRIDE, leave it in place. Touch only this branch's folder, not any
other task folders that happen to be in active/. Report what was moved.
    Folders tagged CAP_REACHED or OVERRIDE stay in active/ on purpose. A human handles those by hand. If you review one and decide to set it aside instead of fixing it, move it to ai_coding/quarantine/ rather than archive/. Quarantine is the "looked at, not resolved" pile.
  7. Run /clear when Claude tells you to. Claude will say something like "deep review complete. run /clear before starting the next feature." Type /clear in the Claude Code chat. That wipes its memory of this work so the next task starts fresh. Do not run /clear earlier. That would erase the context the deep review needs.
  8. Push the branch and open a pull request. 
    git push -u origin task/short-name
gh pr create --base master
    The automated checks start on their own. The merge gate looks at every commit on your branch and confirms each one has valid AI-Verdict: and AI-Task: lines at the bottom.
  9. Squash and merge when the checks pass. Use the green merge button on GitHub. Delete the branch when GitHub offers to.

What you never have to do

  • Create the task folder by hand. A hook stops Claude from editing source files until the folder exists, so Claude makes it.
  • Remember to add the AI tag lines. The local commit hook will reject the commit if they are missing.
  • Worry about Claude editing files before the folder exists. The same hook blocks any edit outside ai_coding/active/<task>/ until a task folder is in place.
  • Manually copy diffs into task folders. A post-commit hook does that for you.

Common edge cases

The CI merge gate failed on my pull request

Two common causes. (1) A commit on the branch is missing the AI tag lines. Find the bad commit in the failed check log and either rewrite it or replace it. (2) A commit has AI-Verdict: CAP_REACHED or AI-Verdict: OVERRIDE. The gate blocks these on purpose so a human reviews them first. Decide whether the override is fine. Then either rewrite the history so the verdict is PASS, or merge with an admin override.

I want to work on something small and skip the pipeline

Use a branch name that does not start with feature/, fix/, or task/. Do not add anything under ai_coding/active, ai_coding/archive, or ai_coding/quarantine. The merge gate will skip the check and your pull request goes through normal review. The Claude Code hooks still block edits to source files until a task folder exists, so to bypass the local commit hook on a quick commit, use git commit --no-verify.

Claude went off the rails and I want to start over

Delete the task folder under ai_coding/active/, reset your branch with git reset --hard origin/master, and begin again. The pipeline does not keep any state outside that folder.
