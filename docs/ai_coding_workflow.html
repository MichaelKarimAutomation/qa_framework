AI Coding Workflow (Human Steps)

What you do when using Claude Code in this repo. Claude does the rest of the work on its own. If you want the full reasoning behind any step, read CLAUDE.md. That file is the rule book.

Steps

  1. Update master and start a new branch. 
    git checkout master && git pull
git checkout -b task/short-name
    Pick a short name written in lowercase words joined by hyphens (for example task/add-login-button). The name should say what the change is about. On Windows PowerShell, replace && with ;.
  2. Tell Claude Code what you want in plain words. Just describe the change. Claude follows the pipeline on its own: it creates the task folder, writes tests, runs them, performs a deep review of its own diff, and makes a commit with the special tag lines at the bottom. Hooks back this up by blocking edits outside the task folder and rejecting commits missing the tag lines.
  3. Watch progress in ai_coding/active/<your task>/PROGRESS.md. Claude writes to this file at the important moments. You do not edit it yourself. Reading it tells you what is finished and what is left.
  4. Answer the deep-review prompt if Claude finds issues. After the tests pass, Claude performs its own deep review of the diff and writes the findings to ai_coding/active/<your task>/review.md. If the review verdict is PASS, Claude commits and moves on. If the verdict is FAIL, Claude stops and asks you in chat: "Deep review found issues: fix, or accept as OVERRIDE?"
    • Say fix and Claude addresses the findings, then re-reviews. Repeat as many times as you like; there is no cap on this loop.
    • Say override and Claude rewrites the review verdict to OVERRIDE, logs the accepted issues to disagreements.log, and commits with AI-Verdict: OVERRIDE.
    Either way, the commit succeeds and the CI merge gate passes.
  5. Check disagreements.log when Claude halts. Open ai_coding/active/<your task>/disagreements.log. You will see one of these tags:
    • [TEST_CAP_REACHED]: tests still failed after 3 fix attempts. No commit was made.
    • [FULL_SUITE_FAILED]: something Claude did not touch is now broken. No commit was made.
    • [OVERRIDE]: you accepted Claude-flagged issues. The commit exists and is allowed through the merge gate.
    For the two halt tags (no commit yet) you can fix the problem yourself, give Claude new instructions, or drop the task. For [OVERRIDE] the commit already exists, so you fix on top or redirect Claude if you change your mind.
  6. Push the branch and open a pull request. 
    git push -u origin task/short-name
gh pr create --base master
    The automated checks start on their own. The merge gate looks at every commit on your branch and confirms each one has valid AI-Verdict: and AI-Task: lines at the bottom.
  7. Squash and merge when the checks pass. Use the green merge button on GitHub. Delete the branch when GitHub offers to.
  8. Auto-archive runs on merge. Nothing to do. A GitHub Actions workflow runs on every push to master. It scans ai_coding/active/ for task folders with STATUS of PASS or OVERRIDE and moves them into ai_coding/archive/. The workflow's own commit uses [skip ci] so it does not re-trigger the test suite.
  9. Run /clear when Claude tells you to. After the commit, Claude will say something like "commit done. run /clear before starting the next feature." Type /clear in the Claude Code chat. That wipes its memory of this work so the next task starts fresh.

What you never have to do

  • Create the task folder by hand. A hook stops Claude from editing source files until the folder exists, so Claude makes it.
  • Remember to add the AI tag lines. The local commit hook will reject the commit if they are missing.
  • Worry about Claude editing files before the folder exists. The same hook blocks any edit outside ai_coding/active/<task>/ until a task folder is in place.
  • Manually copy diffs into task folders. A post-commit hook does that for you.
  • Manually move finished task folders to archive. The auto-archive workflow does it on master push.

Common edge cases

The CI merge gate failed on my pull request

Usually one cause: a commit on the branch is missing the AI tag lines, or one has a malformed AI-Verdict (must be PASS or OVERRIDE). Find the bad commit in the failed check log and either rewrite it or replace it. OVERRIDE commits pass the gate automatically; no label or extra approval is required.

I want to work on something small and skip the pipeline

Use a branch name that does not start with feature/, fix/, or task/. Do not add anything under ai_coding/active or ai_coding/archive. The merge gate will skip the check and your pull request goes through normal review. The Claude Code PreToolUse hook only blocks edits that Claude makes, so a human editing files directly is unaffected. To skip the local commit-msg hook's trailer check on a quick non-pipeline commit, use git commit --no-verify.

Claude went off the rails and I want to start over

Delete the task folder under ai_coding/active/, reset your branch with git reset --hard origin/master, and begin again. The pipeline does not keep any state outside that folder.

Auto-archive workflow didn't move my folder

Check that ai_coding/active/<task>/STATUS contains PASS or OVERRIDE (and nothing else, no trailing whitespace beyond a newline). If it does and the workflow still didn't move it, run the backup utility locally: python ai_coding/clear_queue.py --task <task>.
